# FPS Tools 1.1.1 音频兼容性修复

基于 v1.1.0（7eca500）独立维护，不合入 FPS Tools Studio 2.0.0。

## 问题与处理原则

用户提供的 30 fps MP4 有 152 帧、一个 AAC 音轨。旧版提示“音轨数据不完整，文件可能被截断”。音频可完整解码，声明和实际解码都是 242688 个采样；封装时间戳有四次各一个采样的舍入差，时间戳终点为 242684。旧版两个时间单位的严格比较导致误拒绝。

按用户确认的规则，音频时间戳不作为完整性保证或拒绝导入的依据：

- 导入和输出验证仅扫描视频及受支持的时间码轨道，音轨只读取基本信息。
- 音轨时间戳误差、空档、重叠、声明时长差异以及音频尾部缺失，不再单独阻止完整视频的处理。
- 正常音轨仍使用原有变速和音调保持流程；起点位于视频结束之后时改从零开始。仍保留音轨数量检查，并报告实际无法编码或写出的错误。
- 同帧率导出直接复制，不要求存在音频编码器。
- 视频帧数、CFR 时间轴、末帧时长、编码包 SHA-256、编码参数和属性检查全部保留。

## 验证

- 自动化测试 72 项通过，包括 GUI 导入/导出、MP4/MOV/M4V、44.1/48 kHz、音频空档和重叠、音轨超晚起点、音频缺尾、视频损坏/截断、连续改帧率、时间码、多音轨和音调保持。
- 用户附件实测 24、25、30、60、30000/1001 fps，均为 152 帧、视频包哈希一致、保留一个音轨；30 fps 输出与原文件逐字节一致，原文件未改动。
- 回归测试使用程序生成的测试视频；用户素材及其导出结果仅保存在本地，未加入仓库。
- 本地 macOS arm64 自包含应用构建及隔离 PATH 冒烟测试通过；在打包后的真实界面导入用户附件并导出 24 fps，显示成功 1 个、失败 0 个。
